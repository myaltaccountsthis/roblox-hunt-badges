# Roblox badges — The Hunt 20

A local web dashboard and command-line API scraper. Requires Node.js 22.13 or newer. No Roblox account, API key, or paid service is needed for the public badge endpoints.

## Run the web interface

```powershell
cd "$env:USERPROFILE\Documents\robloxbadges"
npm install
npm run dev
```

Open http://localhost:5173. Dependencies are already installed in this checkout, so skip `npm install` unless setting up a fresh copy.

The dashboard requests all 40 badge details using `https://badges.roblox.com/v1/badges/{badgeId}`. Every 60 seconds, it rescans the 20 game catalogs and refreshes statistics. **Force refresh** bypasses the short server cache. Requests go through the server to avoid browser CORS restrictions. Automatic updates run while the dashboard is open; browsers may slow background tabs. Use the CLI watcher for continuous polling independently of a tab.

## Scraper and files

```powershell
npm run scrape                  # Refresh statistics for saved badge IDs
npm run discover                # Re-read the spotlight, scan every catalog page, and update all files
npm run watch                   # Discovery + statistics every minute until Ctrl+C
npm run check                   # Run the small regression check
npm run build                   # Production build
npm start                       # Serve the production build locally
```

- `data/badges.json`: annotated registry with all IDs as strings, game names, universe IDs, source links, selection notes and timestamps.
- `BADGE_IDS.md`: human-readable game-to-badge list and uncertainty notes.
- `public/badges.csv` and `public/badges.json`: export files generated by the scraper.
- `data/snapshot.json`: last fetched badge API responses, including counts, enabled state and fetch errors.
- `scripts/scrape.mjs`: CLI entry point; `lib/roblox.mjs`: shared discovery, selection and API code.

Web downloads reflect the dashboard's current live catalog. The web server keeps updates in memory; use `npm run discover` or `npm run watch` to update the local files. No background scheduled task is installed.

## How badges are selected

The official [event spotlight](https://www.roblox.com/spotlight/the-hunt-roblox-20) embeds all 20 game universe IDs. The scraper follows all pages from `https://badges.roblox.com/v1/universes/{universeId}/badges?limit=100&sortOrder=Desc`, then sorts by the **creation timestamp**, because creator-defined catalog ordering is not always chronological and badge IDs do not establish recency.

1. **Secret quest:** a badge created during the event preparation period (September 2026 onward) explicitly says “secret quest” in its name or description.
2. **Candidate:** a newly created badge has an obscure or placeholder name, or it is the newest of multiple event-period badges. Likely secret, but the note states that this is an inference. Blade Ball's obscure badge is slightly older than its named main-quest badge, so it is selected despite not being the newest.
3. **Reference only:** no identifiable secret badge is exposed. The newest public badge is included as a clearly labeled reference, even if it is a main-quest or unrelated badge. It is not claimed to be a secret.

The initial discovery found 5 explicitly labeled secret quests, 10 candidates and 5 reference-only game badges, plus the 20 supplied hub badges. These counts can change as Roblox updates its catalogs. The S01–S20 badges belong to **The Hunt: Roblox 20 hub**, universe `10766456501`. Their S-numbers do not establish which individual event game they correspond to.

The Roblox `enabled` flag does not establish whether a quest has been released. Award counts are global, not the current player's inventory. “Past 24 hours” uses the API's `pastDayAwardedCount` field unchanged. No award counts are fabricated.

## Reliability

- At most 3 catalog requests and 4 badge-detail requests run concurrently.
- Timeouts and bounded retries handle transient failures and HTTP 429; `Retry-After` is respected. Long backoffs wait for the next polling cycle.
- Failed badge requests retain last-known values and show a stale label. Failed discovery retains the previous selection and shows a warning.
- Polls never overlap in the same page or server isolate. Server cache is 55 seconds, with force refresh and in-flight request coalescing.
- Initial saved snapshots are never presented as fresh results.
- A failed spotlight discovery preserves existing catalog files instead of silently dropping games.
- Cache is in-memory and per server/Worker isolate. This is suitable for personal use; a busy public deployment would need shared caching.
- Experimental WebMCP `refresh_badges` invokes the same refresh action where supported.

See the [official API documentation](https://create.roblox.com/docs/cloud/reference/domains/badges).

## Confirming and replacing badges

Game icons come from Roblox's public thumbnails API. Gold highlighting means the badge has **more than 2 total awards**; it does not independently confirm that it is a secret badge.

Use **Confirm** to mark a candidate correct. Use **Add badge** on a reference row, or **Change** on any game row, to enter a badge ID or Roblox badge URL. The server checks that the badge is awarded by that game before accepting it. **Reset choice** restores automatic discovery.

Choices and confirmations are saved only in this browser's local storage and survive page reloads. They are included in dashboard CSV/JSON downloads. They are not shared across browsers and do not rewrite the CLI's catalog on disk. For local file updates, download the current catalog or run the scraper. Confirmed choices stay pinned when newer candidates appear.

Reference-only game badges are excluded from award highlighting, regardless of their count. Highlighted game rows must be candidates, explicitly identified secret quests, or confirmed by you, with at least 3 awards. Supplied hub badges retain their award highlighting.
